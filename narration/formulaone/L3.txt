Formula One, level 3. We log in as formulaone3 (uid=20003, L2's password) and face /formulaone/formulaone3 - a setuid binary with no stack canary that reads its command structure from a SysV shared-memory segment. Goal: /etc/formulaone_pass/formulaone3. The source shows the double-read: the echo structure's sz field is loaded ONCE for the sz <= 0xff sanity check, then loaded AGAIN for the memcpy that copies echo->ptr onto the stack - with a puts() call in between. Because puts can modify memory through arbitrary pointers, the compiler must re-load sz; that re-load is the race window. The shm segment is mapped SHM_EXEC (RWX) and the binary reads its payload straight from it. f1l3.c (typed in vi, compiled live) creates the SAME shm segment first - key 0xADC00ADC, 8KB, mode 0777 - so when the setuid binary attaches, it attaches to OUR memory. A toggler flips sz between 10 and 0x400 as fast as it can: when the binary's check reads 10 it passes, and if the re-read just before the memcpy sees 0x400, one kilobyte of our data - 'A' padding with the ret-slot dword at +0x110 - smears over the stack. The second argument, 0xf7fb9000, is the measured address where the executable mapping lands, so the smashed return lands in our shm where the payload waits. timeout 100 f1l3 0xADC00ADC 0xf7fb9000 piped through a grep for long alphanumeric strings prints O50RB7ijle1PYuGyw595NuU9O8S49b4o, and cat /etc/formulaone_pass/formulaone3 confirms it - the same string the cast used to log in as formulaone3. Level 3 done.
