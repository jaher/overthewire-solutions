Utumno, level one. I log in as utumno one. The binary takes a directory argument, walks its entries, and for any entry whose name begins with s h underscore it calls a function that copies the name into a writable executable page and jumps into it. So the file name is the payload. We read the disassembly to confirm the flow. Main calls mmap with protection seven, which is read, write and execute, keeps the address in a global, opens the directory, compares the entry name with the three bytes s h underscore, and calls the runner with the name plus three. The runner copies the string into the mapped page and calls it. So execution starts at the fourth character of the file name. The stack is executable and address randomisation is off. Two constraints follow. A file name cannot contain a slash, so the shellcode cannot push slash bin slash sh as the usual pair of immediate values. And the copy stops at a null byte, so the shellcode cannot contain a zero either. I open vim and write the shellcode with those constraints in mind: The header, and the user-id block begins with a zeroed eax. geteuid, then setreuid with the id in all three slots, then the start of setuid. Syscall numbers are loaded with mov al so no instruction contains a zero. setuid follows, so the shell keeps the effective id across execve: a plain setreuid would leave the saved id at utumno one and the shell would drop back. Then the path build begins: reserve eight bytes and store the first slash, made from a dot plus one. Slash is never stored as an immediate. Then b, i, n, and the second dot, each loaded into the low byte and stored. Then the second slash, s, h, and a zero for the terminator. Then the terminator and the execve call. We assemble with nasm, inspect the encoding with objdump, extract the text section with objcopy, and print the bytes with xxd. Wc counts eighty six bytes. A small python check prints the length, eighty six, and confirms no slash and no null. Then the exploit creates the file: s h underscore followed by those eighty six bytes. Running the binary on that directory executes the shellcode. The password for utumno two is W a S w u X N h v g.
