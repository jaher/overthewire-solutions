Utumno, level three. The disassembly is a short loop. For each iteration it stores the current value into the table at index k, exclusive ors it with three times k, reads a new value from getchar, and then writes that value to table at index equal to the signed char of the exclusive or result. Then it reads another value, stops at end of file or after twenty four iterations. The index is a signed char used as an offset, so it reaches from table minus one hundred twenty eight to table plus one hundred twenty seven. That covers the saved return address at table plus forty, and also argv zero at table plus forty four. We confirm the arithmetic in gdb: a small payload that writes to index thirty six changes the saved return address exactly as predicted. The first iteration is special, because the value starts at zero, so the selector byte is zero, and each iteration consumes exactly two input bytes. Getting that off by one wrong shifts the whole payload. The stack is executable and address randomisation is off, so we can put the shellcode in argv zero, which is a string we control, and overwrite the return address with its address. Only four writes are needed. We write the shellcode in vim. It prints a marker, raises the user id, then opens and reads the password file itself, because the getchar loop has already consumed all of standard input, so a spawned shell would have no commands. The path is pushed as six little endian words. We assemble with nasm and extract with objcopy. The exploit builds the twenty four byte input from the formula, with the selector byte equal to the index exclusive or three k, and the value byte as the target. The sweep over return addresses hits f f f f d f six four, which is inside argv zero, and the shellcode prints the password zero six n x two C S seven r S. We verify.
