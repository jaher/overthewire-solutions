Utumno, level two. Running it with no arguments prints a short message and exits one. The disassembly shows why. The guard wants exactly one argument, and that argument must be the empty string: argc equal to one, and the first byte of argv zero is zero. Python refuses to build an empty argv zero. The execve call says the first element cannot be empty. So we call libc dot execve directly through ctypes, with a pointer array we build ourselves. The second quirk is the copy source. The program does strcpy into a twelve byte buffer, but the source is argv ten, which is ten pointers past the start of argv. With one argument, argv ten is past the null terminator, inside the environment array. The kernel puts envp immediately after argv on the initial stack, so argv ten is envp eight, the value of the ninth environment variable. That gives us a full string to copy. Twelve bytes fill the buffer, the next four overwrite the saved frame pointer, and the next four the return address. We confirm the alias with a tiny C wrapper, because Python cannot pass an empty argv zero and gdb needs a real binary. The wrapper has argv equal to empty string and null, and eleven environment variables. In gdb, breaking just before the strcpy, the source pointer holds the ninth environment variable, and the buffer and return address offsets are confirmed. We write the shellcode in vim: a marker write, then geteuid, setreuid and setuid, then execve slash bin slash sh, all null free because the payload is a C string. We assemble with nasm, objdump the object to see the encoding, extract with objcopy, and check the bytes with xxd. The environment value is the prefix E zero eight equals, then eight nops, then the shellcode, then four filler bytes, then the return address. The exploit forks once per candidate address and looks for the marker in the child output. The sweep hits at f f f f d c d zero.
