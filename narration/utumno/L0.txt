Utumno, level zero. The binary is execute-only: its permissions are three dashes, then x, then three dashes, then x, then three dashes. The x bits let us run it, and the missing r bits stop us opening it. So every ordinary tool fails. Strings says permission denied. Objdump says permission denied. Nm and readelf and ltrace all refuse, and copying the file out fails too. Ptrace is refused as well, because a process tracing another needs to read the file. The binary prints one line, read me, and exits. But the file permission governs opening the file, not reading the pages the kernel maps for the running process. Once the program is loaded, those pages belong to the process, and the process may read them. So we write a shared library whose constructor runs before main. It opens proc self maps, finds the four segments belonging to the level binary, and writes each readable one into a file. The binary is thirty two bit, so we must compile the library with gcc minus m thirty two. A sixty four bit library is rejected by the loader with wrong ELF class. The first attempt with plain gcc minus shared produced exactly that error, and nothing was dumped. With minus m thirty two we get a sixteen kilobyte image of the four segments. Now the dumped image can be treated like any binary. Strings shows the password as a plain literal in the read-only data, and disassembling main with objdump, treating the image as raw code at its load address, shows it storing the address of the password string and pushing the read me string before calling puts. The disassembly and the dump agree, so the dump is genuine. The password is g zero V p i w three a Z t. We verify by logging in as utumno one.
