Narnia, level three. This one is not about the return address; it is a stack variable overflow. The source declares an input filename buffer of thirty-two bytes and an output filename buffer of sixteen bytes initialised to slash dev slash null. It then does a strcpy of argv one into the input buffer. Because the input buffer overflows, the bytes beyond the first thirty-two spill into the output buffer, which sits above it on the stack. The program opens the output file read-write, opens the input file read-only, and copies thirty-one bytes between them. Our trick is to craft one argument that is both a valid directory path and a writable output path. We make a directory under slash tmp whose name is twenty-seven letter A's. The argument is slash tmp slash those twenty-seven A's slash tmp slash out three. The first thirty-two bytes of that string fill the input buffer and form a real directory path. The bytes after position thirty-two become the output filename, slash tmp slash out three. Inside that directory we place a symbolic link named out three pointing to the password file for the next level. We also pre-create slash tmp slash out three as a world-writable file so the program's open for writing succeeds. The setuid program reads the password through the link and writes it to the output file, which we can now read. We read the password and log in as the next level to verify.
