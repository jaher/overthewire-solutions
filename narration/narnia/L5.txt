Narnia, level five. This is the classic format string level. The source declares an integer i, set to one, and a sixty-four byte buffer. Then it calls snprintf with the buffer as destination, sixty-four as the size, and argv one as the format string. That is the bug: user input is used as a format string. The program checks whether i equals five hundred. If it does, it prints GOOD, switches to the next user, and gives us a shell. Otherwise it prints a hint, including the value of i and its address. Our weapon is the percent n conversion, which stores the number of characters printed so far into the pointer given as the corresponding argument. First we inspect the binary. Disassembling main shows i initialised at ebp minus eight and the buffer at ebp minus forty-eight, so i sits exactly sixty-four bytes above the buffer. Then gdb shows something crucial: the destination buffer of snprintf overlaps the varargs area on the stack. The first vararg slot holds the size, sixty-four, and the buffer itself begins just after it. That means the format string reads its own output, and vararg k is simply buffer plus four times k minus one. We confirm this by running the program with a format string full of percent x conversions; the printed values are bytes of the string itself. The address of i changes with the environment, but the program prints it for us, so the exploit first runs the binary with an argument of the same length and the same empty environment, reads the address from that hint, and then builds the real payload. The payload is fifty-six filler bytes, then the four-byte address of i, then percent four forty c, then percent fifteen dollar n. The filler puts the address at offset fifty-six, which is vararg fifteen. The four forty c prints four hundred forty characters, bringing the total to five hundred. Then percent fifteen dollar n stores five hundred into i. The check passes, GOOD is printed, and we get a shell as narnia six. We read the password and verify it by logging in.
