Narnia, level two. Main copies argv one into a one hundred twenty-eight byte buffer with strcpy, and there is no length check. I log in as narnia two, change to slash tmp, and read the source. The disassembly shows the buffer at ebp minus one hundred twenty-eight, so the saved frame pointer sits at offset one hundred twenty-eight and the return address at offset one hundred thirty-two. Readelf shows the stack is readable, writable and executable, and address randomisation is zero, so a return into the stack will run. Before writing assembly, I prototype the payload logic in C. It prints the marker PWN exclamation, reads the effective id, sets reuid with it twice, sets uid with it, then execs the shell. I print the prototype with cat, compile it with gcc minus m thirty-two, and run it: it prints PWN exclamation and the effective id, so the syscall order is right. Then I write the shellcode in vim. It starts with a write of the four byte marker PWN exclamation, so the address sweep can tell a hit from a crash. Then geteuid, syscall two hundred one, and setreuid with that id twice, syscall seventy, so the effective id survives the exec. Then setuid with the same id, syscall twenty-three, which sets the real, effective and saved ids, so the privilege survives the exec where a plain setreuid would not. Finally execve on slash bin slash sh, syscall eleven. I print the finished assembly with cat. I assemble it with nasm, format elf thirty-two, extract the text section with objcopy, and print the bytes with xxd. Before the bytes go into argv one, I prove they work on their own: a small C harness maps a page readable, writable and executable, copies the assembled bytes in, and calls them. I print the harness with cat, compile it, and run it on the assembled bytes: it loads seventy-eight bytes, jumps in, and the shellcode prints PWN exclamation, so the code is proven before it goes into the overflow. Then I write the exploit driver in vim. It loads the shellcode from the assembler output, and checks it has no null byte and fits in one hundred twenty-eight bytes. The payload is fifty NOPs, then the seventy-eight byte shellcode, then four B bytes for the saved frame pointer, then the return address in little-endian. The probe runs the binary with a candidate address, writes echo PROBE OK to its standard input, and counts a hit only if PROBE OK comes back, because the program echoes the payload, which itself contains PWN exclamation, so grepping for the marker would report hits that never ran. The sweep runs from ffff d zero zero zero to ffff e eight zero zero, four bytes at a time, skipping any address whose little-endian bytes contain a null. I print the driver with cat, then run it. It hits at ffff d one e eight after one hundred twenty-three probes, runs the shell as narnia three, and the password prints. The shell runs as narnia three, and the level is solved.
