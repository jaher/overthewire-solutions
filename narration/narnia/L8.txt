Narnia, level eight, the last level of the game. The vulnerable function declares a pointer called blah, initialised to the argument, and a twenty-byte buffer called bok. It zeroes bok, then runs a copy loop: for each index i while blah at i is not zero, it copies blah at i into bok at i. There is no bounds check, so the copy overflows the buffer. We inspect the layout. Disassembling shows bok at ebp minus twenty-four and the local pointer blah at ebp minus four. That means bok bytes zero through nineteen are the array, bytes twenty through twenty-three are the pointer itself, bytes twenty-four through twenty-seven are the saved frame pointer, and bytes twenty-eight through thirty-one are the return address. The trap is subtle: at index twenty, the loop overwrites its own source pointer, so after that it reads from wherever the new pointer value points, and it usually hits a zero byte and stops before reaching the return address. The fix is to make the four bytes at offset twenty equal the address of the argument string itself, so the pointer keeps pointing at readable data. We confirm the stack is executable and address randomisation is off. We write the shellcode in assembly, assemble it with nasm, disassemble it with objdump, extract the raw bytes with objcopy and print them with xxd. Then we need the address of the argument string. We find it with a segfault oracle: we put an invalid return address in the argument, sweep the four bytes at offset twenty, and look for the run that prints the buffer and then crashes, which means the loop reached the return address. That gives the argument address, which is fixed because randomisation is off. The payload is twenty NOPs, then the argument address, then filler, then the return address pointing into a NOP sled at the argument plus thirty-two, then the shellcode. The program prints the buffer, then our marker, and gives us a shell as narnia nine. We read the password, verify it by logging in, and the congratulations file confirms the game is complete.
