Narnia, level six. The source declares two eight-byte buffers, b1 and b2, and a function pointer fp initialised to the address of puts. It wipes the environment and the extra arguments, copies argv one into b1 and argv two into b2, and then checks a guard: it rejects fp if its top byte equals the top byte of the stack pointer. That guard blocks pointing fp at the stack. Finally it switches to the next user and calls fp with b1 as the argument. Our plan is to overflow b1 into fp and point it at a libc function, system, because a libc address does not have the forbidden top byte. First we inspect the binary. Disassembling main shows fp at ebp minus twelve and b1 at ebp minus twenty, so b1 plus eight is exactly fp: a strcpy longer than eight bytes overwrites the pointer. We confirm in gdb by breaking before the first strcpy and printing the three addresses. Next we find system. ldd shows the thirty-two-bit libc loaded at base f7d6d000. nm on that library gives the offset of system, fifty-three c e zero. Adding them gives f7dc0ce0, and its top byte is f7, not ff, so the guard accepts it. There is a subtle trap: b2 ends exactly where b1 begins, so a long second argument makes strcpy write its null terminator onto the first byte of b1. We prove this in gdb: after an eight-byte b2, b1 is empty and fp is back to its original value. So the second argument must be just one character. The first argument is eight bytes of command, sh semicolon hash, then the four bytes of the system address. Because there is no null between them, the address bytes would become part of the command, but the hash starts a comment, so the shell ignores them. The program calls system with that string, the comment hides the trailing bytes, and we get an interactive shell as narnia seven. We read the password and verify it by logging in.
