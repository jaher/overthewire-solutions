Narnia, level one. The program does something unusual: it takes the environment variable named EGG, casts it to a function pointer, and calls it. So whatever bytes we put in EGG are executed as machine code. The plan is to place shellcode in that environment variable. But first we have to write it. We open vim and create an assembly file, BITS 32, with a _start label. The shellcode does three things. First, it calls geteuid to learn the effective user id, which is narnia two because the binary is setuid. Then it calls setreuid with that id twice, for both the real and effective ids. This step matters: without it, when we later exec a shell, the kernel drops the privilege and we fall back to narnia one. Finally it calls execve on slash bin slash sh. Every instruction is chosen to avoid a null byte, because the environment cannot carry one. We then assemble the file with nasm, format elf32, disassemble it with objdump to check the encoding, and extract the raw text section with objcopy. The bytes are placed after a long NOP sled. We run the binary with execve from Python and pass the environment as raw bytes, because Python's normal environment encoding would corrupt the NOP bytes. The program calls our code, the shell comes up as narnia two, we read the next password and log in to verify it.
