Natas, level twenty-eight. The search form takes our query and encrypts it, then redirects to a search page that decrypts it and runs a database query. There is no source code this time, so we treat it as a black box. We post queries of different lengths and look at the ciphertext. The size jumps in steps of sixteen bytes, so this is a block cipher with sixteen-byte blocks. We then post sixty-four identical characters, and the ciphertext contains three identical blocks. That tells us the mode is ECB, the electronic codebook mode, where every block is encrypted independently. Because of that, we can cut blocks from one ciphertext and paste them into another, and the decryption still succeeds. Next we find where our input starts. Queries of eight and twelve characters share a block, and thirteen changes it. That means there is a ten-byte prefix before our input, and six of our characters fill the rest of that block. Our input starts at block three. Now we build a second query that begins with ten filler characters so that our SQL payload starts exactly at block three. We take the first three blocks from a harmless query, which contain the prefix, and append the blocks from our payload query. The server decrypts the spliced ciphertext and sees our union select, which returns the password from the users table. The lesson is that ECB mode leaks structure and allows block splicing, so it must never be used for data where the attacker can submit plaintext. We read the password and verify it by logging in.
