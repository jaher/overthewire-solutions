Natas, level twenty-seven. The page is a login form backed by a user table with sixty-four character username and password columns. Registration refuses names that differ from their trimmed form, and it stores only the first sixty-four characters. Login compares the whole string exactly, and then dumps the row whose username equals the trimmed input. Three quirks combine. First, if we register a name that is sixty-five characters long, ending in a non-space character, the trim check passes, but the insert cuts it to sixty-four characters. So we register the string natas28 followed by fifty-seven spaces and then an x. The stored username becomes natas28 followed by fifty-seven spaces, with our own empty password. Second, MySQL ignores trailing spaces when comparing strings, so the padded name matches that row and the login check passes. Third, the data dump trims the username before querying, which turns our padded name back into natas28, selects the genuine natas28 row, and prints its real password. The recording shows the registration, the padded login, and the dumped row with the password. The lesson is that different layers trim, truncate and compare strings in different ways, and mixing those behaviours creates identity confusion. We read the password and verify it by logging in.
