Natas, level twenty-four. The page prints the credentials when the negation of strcmp of our password and the secret is true. That is the standard way to test a password: strcmp returns zero when the strings are equal, so negating it means the password matched. The flaw is that strcmp expects two strings, and PHP lets a request deliver an array. If we send the parameter as passwd with square brackets, the request parser builds an array, and that array is what reaches strcmp. Passing an array where a string is expected makes strcmp emit a warning and return null. Negating null gives true, so the condition passes without the password ever being compared. We first send a normal string and get wrong. Then we send the array form, and the response shows the warning followed by the credentials for natas twenty-five. The lesson is type confusion: validate the type of user input before using it, and never rely on a warning to stop execution. We read the password and verify it by logging in.
