Natas, level thirty-three, the final level. The page uploads a firmware file. An executor class stores the filename from the form, moves the upload to a directory under the slash natas thirty-three path, and at the end of the request it checks the md five of that filename against a fixed signature. If they match, it runs the php interpreter on the file. The filename and signature are private properties, so we cannot set them through the form. But the upload lets us choose where the file is written, and that choice becomes the filename used in the check. Here is the trick. If the filename is a phar uniform resource locator, then the md five function opens a phar stream. Opening a phar makes php deserialize the metadata stored inside it. And the metadata is completely under our control. So we build a phar whose metadata is a serialized executor object, with a filename pointing to our own php payload and a signature equal to the md five of that payload. When php rebuilds the object from the metadata, its destructor runs at the end of the request. The check now compares our payload's md five with the signature we stored, so it matches, and the page runs php on our payload. The payload reads the natas thirty-four password file. The phar itself has to be well formed, with a proper stub, manifest, signature and trailer, so we write a small python builder to produce it. The lesson is that deserialization can be triggered by file operations, not just by unserialize calls, and that private properties do not protect an object from being reconstructed from serialized data. We read the password, verify it, and natas is complete.
