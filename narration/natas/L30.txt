Natas, level thirty. The page is a Perl login form. The source builds a SQL query by concatenating two calls to the database handle's quote function, one for the username and one for the password. That function escapes quotes properly, so a normal string injection does not work, and indeed our first attempt fails. But quote has an optional second argument, the SQL data type. And in Perl, the CGI parameter function returns a list when the same parameter appears more than once. So if we send the password field twice, the first value becomes the string to quote and the second value becomes the type. We send password as the injection one or one equals one, and then a second password value of four. Four is the DBI constant for integer. When quote is told the value is an integer, it does not quote it at all, so our injection is spliced into the query as raw SQL. The condition becomes true for every row, and the first row, the natas thirty-one account, is printed. The lesson is that a safe escaping function can be made unsafe by controlling its extra arguments, and that a list where a scalar was expected is a classic type confusion. We read the password and verify it by logging in.
