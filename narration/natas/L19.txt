Natas, level nineteen. The page says the session identifiers are no longer sequential, but the source tells us exactly how they are built. The function takes a random number between one and six hundred forty, appends a hyphen and the username, and then hex-encodes the whole string. So the admin session identifier is simply the hex encoding of some number followed by hyphen admin. Hex encoding does not add any real entropy; it is just a different representation. We brute-force the number: for each value from one to six hundred forty, we build the string, hex-encode it, and send it as the session cookie. Exactly one of them belongs to the admin session. When we hit it, the server loads the admin session and prints the credentials. The winning number is two hundred eighty-one, whose identifier is the hex of two eight one hyphen admin.
