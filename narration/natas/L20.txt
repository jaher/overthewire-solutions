Natas, level twenty. This level uses a custom session save handler instead of the default PHP serialization. The write handler stores each session variable as a line containing the key, a space, and the value. The read handler rebuilds the session by splitting every line on the first space. The page lets us change a name, which is stored as a session variable. I fetch the source and pull out the two handler functions, my read and my write. The flaw is that the value is written verbatim, without escaping newlines. So if we submit a name that contains a newline followed by the text admin space one, the session file ends up with a second line reading admin one. On our next request, the read handler parses that line as the session variable admin with the value one. So I open vim and write the injection: The first chunk sets up the imports, the basic auth header, the page URL, and a cookie jar with an opener that keeps the session cookie across requests. It builds the cookie jar first, then the opener with a cookie processor around it. The second chunk posts the name with the embedded newline, then requests the page again with the same session, and prints whether we are an admin and the credentials block. The name is x, newline, admin space one, and the print falls back to the first two hundred characters when there is no credentials block. I run it, and the reply says we are an admin, and it prints the password for natas twenty-one, and the level is solved. The lesson is that custom serialization must escape the characters it uses as separators, or a value can smuggle in new keys.
