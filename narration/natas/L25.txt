Natas, level twenty-five. The page loads a language file from the language directory, using the lang parameter. The include helper tries to block directory traversal by searching for dot dot slash and removing it with a string replace, and it also blocks any path containing the password directory name. But there are two flaws, and they chain together. First, whenever a traversal is detected, the page writes a log entry. That entry contains our user agent header, written verbatim, into a log file inside the web root whose name contains our session id. So we can write PHP code into a file that the server will later execute. Second, the removal of dot dot slash is a single pass. If we send four dots followed by two slashes, the replace finds the dot dot slash starting at the second dot and removes it, which leaves dot dot slash behind. The traversal survives. So we start a session and read its id from the cookie jar. We send a request with a deliberate traversal in lang and PHP code in the user agent, which writes our code into the log. Then we include that log using the four dots two slashes form, and the PHP inside it runs and prints the password for natas twenty-six. The lesson is that string filters that run once can be defeated by overlapping patterns, and that logging attacker input into an executable location is dangerous.
