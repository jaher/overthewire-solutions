What it does instead is create a session identifier using a random number between one and six hundred forty, and it stores an admin flag in the session. The credentials are printed only when that flag equals one. I fetch the source and pull out the maximum session id, six hundred forty. The flaw is that the session identifier space is tiny and guessable: exactly one of those identifiers belongs to a pre-existing admin session, and the server loads that session when it sees the cookie. So I open vim and write the brute force: The first chunk sets up the imports, the page URL, the basic auth header, and the loop over session ids from one to six hundred forty, starting the request with the session cookie. The second chunk fetches each session, and when the reply says you are an admin, it prints the session id and the credentials block, then stops. Here is the second chunk. I run it, and it finds session one hundred nineteen, an admin session, and prints the password for natas nineteen, and the level is solved.
