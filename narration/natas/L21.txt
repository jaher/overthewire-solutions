Natas, level twenty-one. The main page checks a session variable called admin and prints the credentials when it equals one. The page notes that it is colocated with an experimenter site that shares the same session storage. Reading the experimenter's source reveals the flaw: when it receives a submit request, it copies every request parameter directly into the session, so the key and value we send become session variables. Because the two sites share the session store, we can post admin equals one to the experimenter, and that value is written into the shared session. The experimenter returns a session identifier cookie. We then take that same identifier to the main site, which loads the shared session and sees admin equals one. So I open vim and write the session transfer: The first chunk sets up the imports, the basic auth header, the two site URLs, and the form data: submit one, admin one, and the colour settings. The form data also sets the background colour to white, the alignment to left, and the font size to one hundred percent. The second chunk posts that data to the experimenter with a ten second timeout, then loops over the set cookie headers, splits the session id out on the semicolon, and prints it. Then it requests the main site with the same identifier and a ten second timeout, reading the reply as text. The last chunk finds the credentials block and prints whether we are an admin and the block itself. I run it, and the main site sees admin equals one and prints the password for natas twenty-two, and the level is solved. The lesson is that sharing sessions between applications is dangerous when one of them lets clients write arbitrary session keys.
