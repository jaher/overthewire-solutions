Natas, level twenty-one. The main page checks a session variable called admin and prints the credentials when it equals one. The page notes that it is colocated with an experimenter site that shares the same session storage. Reading the experimenter's source reveals the flaw: when it receives a submit request, it copies every request parameter directly into the session, so the key and value we send become session variables. Because the two sites share the session store, we can post admin equals one to the experimenter, and that value is written into the shared session. The experimenter returns a session identifier cookie. We then take that same identifier to the main site, which loads the shared session and sees admin equals one. So I open vim and write the session transfer: The first chunk sets up the imports, the basic auth header, the two site URLs, and the form data: submit one, admin one, and the colour settings. The second chunk posts that data to the experimenter, pulls the session identifier out of the reply cookies, prints it, and requests the main site with the same identifier. The last chunk finds the credentials block and prints whether we are an admin and the block itself. Here is the last chunk. I run it, and the main site sees admin equals one and prints the password for natas twenty-two, and the level is solved. The lesson is that sharing sessions between applications is dangerous when one of them lets clients write arbitrary session keys.
