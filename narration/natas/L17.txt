The only signal we get is timing. The query includes a sleep call only when our injected condition is true, so a response that takes noticeably longer tells us the condition held. One detail matters: the query matches several rows, so the sleep runs once per row, and a true condition takes about twenty seconds while a false one returns in under a second. This is blind SQL injection through time delays. The approach is the same binary search we used earlier: for each character position, we ask whether the character code is greater than or equal to a midpoint, and we wait for the delayed response to answer yes or no. We first learn the length, which is thirty-two, and then we recover each character with about seven requests.
