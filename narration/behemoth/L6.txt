Behemoth, level six. We log in as behemoth six and look at the two binaries. ls shows behemoth six is setuid to behemoth seven, and the reader is a plain executable owned by behemoth seven. strings on the reader shows it opens a file called shellcode dot txt, and the messages could not open shellcode dot txt, and write your own shellcode. The disassembly shows it opens the file and maps it with read, write and execute permission. It also scans the first four thousand ninety-six bytes and refuses the file if it contains the byte zero x zero b, and then it calls into the mapping. Then we write the shellcode in vim. First the header: thirty-two bit mode, the global entry point, and the start label. It must print exactly ten bytes, HelloKitty, the string the program checks our output against. It pushes the string onto the stack in three pieces, because ten bytes do not fit in one immediate, sets up a write to file descriptor one, and exits. It loads four as the syscall number and triggers the interrupt, then loads one as the exit syscall, clears the exit status, and triggers the interrupt again. We assemble it with nasm, extract the raw bytes with objcopy, and print them with xxd: forty-one bytes, with no zero x zero b byte in them. Then we run the exploit: it writes the bytes to shellcode dot txt in a directory we own and runs behemoth six on a raw terminal. The program answers Correct, we get a shell as behemoth seven, and it prints the password, and the level is solved.
