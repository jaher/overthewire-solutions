Behemoth, level five. We log in as behemoth five and look at the binary. strings shows the calls socket and sendto, the behemoth six password file, the name localhost, and the port thirteen thirty seven. The disassembly shows it opens the password file and reads it, resolves localhost, creates a UDP socket, and sends the contents to port thirteen thirty seven. So the password is not printed to the terminal at all: it is put into a UDP datagram addressed to a fixed local port. Nothing is listening there by default, so the packet is dropped and we see nothing. But UDP does not need a handshake: if we bind that port before we start the program, the kernel will queue the datagram to our socket, and we can receive it. We run the script: it binds to localhost port thirteen thirty seven, starts the program, and waits for the packet. The program reads the password file as behemoth six, because the binary is setuid, and sends it to us: eleven bytes, and the level is solved.
