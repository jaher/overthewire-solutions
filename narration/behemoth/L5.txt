Behemoth, level five. The program opens the behemoth six password file and reads it. It resolves the name localhost, creates a UDP socket, and sends the contents to port thirteen thirty seven. So the password is not printed to the terminal at all. It is put into a UDP datagram addressed to a fixed local port. Nothing is listening there by default, so the packet is dropped and we see nothing. But UDP does not need a handshake. If we bind that port before we start the program, the kernel will queue the datagram to our socket, and we can receive it. We write a small script that binds to localhost port thirteen thirty seven, starts the program, and waits for the packet. The program reads the password file as behemoth six, because the binary is setuid, and sends it to us. The recording shows the listener, the received bytes, and the password itself. The lesson is that data exfiltration to a predictable address can be intercepted by whoever controls that address first. We read the password and verify it by logging in.
