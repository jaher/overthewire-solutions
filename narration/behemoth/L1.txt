Behemoth, level one. We log in as behemoth one and look at the binary. ls shows it is setuid to behemoth two, and file says it is a thirty-two bit Intel executable, not stripped. We disassemble main with objdump: it loads the address of a buffer sixty-seven bytes below the frame pointer and calls gets on it. gets reads until a newline with no bound, so this is a classic stack overflow: the saved frame pointer sits at offset sixty-seven and the return address at offset seventy-one. We inspect the protections: readelf shows the stack is marked executable, and address randomisation is off. That combination means we do not need a return-to-libc chain; we can simply place shellcode on the stack and jump to it. Then we write the shellcode in vim. It writes a marker so our sweep can detect a successful jump. Then it calls geteuid, setreuid with that id twice, and setuid with the same id so the privilege survives the exec. And finally execve on slash bin slash sh. We assemble it with nasm, extract the raw bytes with objcopy, and print them with xxd: seventy-eight bytes. The payload is seventy-one NOP bytes, then the candidate return address, then the shellcode, then a newline. The exploit forks once per candidate address, feeds the payload on standard input, and watches for the marker. When it finds the address that lands in the shellcode, it runs the binary again with that address and feeds the shell commands. We get a shell as behemoth two and read the password, and the level is solved.
