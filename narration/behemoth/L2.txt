Behemoth, level two. We log in as behemoth two and look at the binary. We run strings and grep for touch, cat and sleep: the program builds a touch command and a cat command, and it sleeps. We disassemble main with objdump: it calls getpid and formats a touch command with the process id, then checks the file with lstat and removes it. Then it raises its effective uid to behemoth three with setreuid and runs the touch command. Then it sleeps for two thousand seconds, builds a cat command for the same file, raises its uid again, and runs that. That is the opening: if we start the program in a directory we own, we can wait for the numeric file to appear, delete it, and replace it with a symbolic link to the behemoth three password file. The exploit starts the program in its own work directory, waits for the file named forty-five to appear, and replaces it with the link. The wait is the hard part: two thousand seconds is about thirty-three minutes, and the lab drops idle sessions, so the exploit prints a heartbeat every thirty seconds to keep the session alive. At the end, the password appears. The lesson is that a program that later operates on a file whose name it created earlier, in a directory the attacker controls, gives the attacker a window to swap that file, and the level is solved.
