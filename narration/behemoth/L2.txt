Behemoth, level two. There is no source this time, so we read the behaviour from the disassembly. The program prints a touch command with its own process id into a buffer, checks that file with lstat, removes it if it is not a regular file, raises its effective uid to behemoth three, and runs the touch command. So it creates a file named after its process id in whatever directory it was started from. Then it sleeps for two thousand seconds. After the sleep it builds a cat command for the same process id file and runs it, and this time it is still running as behemoth three. That is the opening. If we start the program in a directory we own, we can wait for the numeric file to appear, delete it, and replace it with a symbolic link to the behemoth three password file. When the program wakes up and runs the cat command, the link resolves to the password file, and because the program is now behemoth three, it can read it. The recording shows the wait. Two thousand seconds is about thirty three minutes, and the lab drops idle sessions, so the exploit prints a heartbeat every thirty seconds to keep the session alive. At the end, the password appears. The lesson is that a program that later operates on a file whose name it created earlier, in a directory the attacker controls, gives the attacker a window to swap that file. We read the password and verify it by logging in.
