Behemoth, level four. We log in as behemoth four and look at the binary. strings shows the file name pattern slash tmp slash percent d, and the calls fopen, sleep and putchar. The disassembly shows it calls getpid, formats the file name, opens the file, sleeps for a second, and then prints it byte by byte. The interesting part is that the process id is not a secret: if we fork first, the parent learns the child's process id before the child does anything else. The child then executes behemoth four, and while it is still starting up and loading libraries, the parent creates a symbolic link at that exact path pointing to the behemoth five password file. Here the window is only milliseconds, but because we predict the process id exactly, the race is deterministic, unlike the earlier level where the program created its own file and slept for half an hour. By the time the program opens the file the link is there, and it prints the password, and the level is solved.
