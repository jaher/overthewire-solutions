Behemoth, level four. The program builds a file name from its own process id under the tmp directory, opens that file, sleeps for a second, and then prints every byte of it. The interesting part is that the process id is not a secret. If we fork first, the parent learns the child's process id before the child does anything else. The child then executes behemoth four, and while it is still starting up and loading libraries, the parent creates a symbolic link at that exact path pointing to the behemoth five password file. By the time the program opens the file, the link is already there, and the program reads and prints the password, running as behemoth five because the binary is setuid. The recording shows the planted link, the program announcing that it finished sleeping and is now reading, and then the password itself. Compare this with the earlier level where the program created its own file and slept for half an hour. Here the window is only milliseconds, but because we predict the process id exactly, the race is deterministic. The lesson is that predictable file names in a world writable directory are unsafe. We read the password and verify it by logging in.
