Leviathan, level five. The setuid binary leviathan five is owned by leviathan six. Strings shows it opens a fixed path in the temp directory, prints the file character by character, then deletes it. Because the temp directory is world writable and the path is fixed, we can replace that file with a symbolic link pointing to the leviathan six password file. When the setuid program opens the path with its elevated privileges, it follows the symlink and reads the protected password file, printing it out. The unlink afterwards removes our symlink, which is why the file disappears. This is a symlink-following vulnerability in a privileged program that trusts a world-writable path. We verify the password by logging in as leviathan six.
