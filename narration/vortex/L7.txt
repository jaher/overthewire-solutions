Vortex, level seven. The goal is the vortex8 password, from /vortex/vortex7: a setuid vortex8 binary that computes crc32 of the first argument and only overflows when it equals a fixed value. The gate is the CRC, and CRC32 is linear over GF two on the message, so any payload can be patched to any target CRC by solving a thirty-two variable linear system over four free bytes. The copy is unbounded, the stack is executable, and main's epilogue pops its return address from ecx minus four, where ecx comes from payload bytes sixty-two through sixty-five, so the return address is read from bytes seventy-four through seventy-seven and lands in our NOP sled. I log in as vortex7. I make a working directory, move in, and copy the binary. The probe first: the level prints the CRC of any wrong argument, test gives f nine three b a one one zero, and the patched probe shows the target digest check at the compare. objdump shows main: the crc32 call, the compare against e one c a nine five e e, and the strcpy into a stack buffer. The epilogue loads ecx from the buffer and pops the return address from ecx minus four. readelf shows GNU_STACK read-write-execute, the stack takes shellcode. I open vim and write the CRC patcher: it solves the linear system. First the crc table and the crc function, byte by byte through the table. Then the solver: thirty-two deltas, one per bit, row-reduced into a basis, and the four patch bytes combined from the target and the message. The file is 56 lines, 1446 bytes. I run it, and it prints the patch, four bytes, and the check confirms the patched message hashes to the target exactly. I open vim and write the exploit: it assembles the payload. First the shellcode, eighty-one bytes: the path built backwards on the stack, then open, read, write, and exit through int eighty, dropping to vortex8's id is unnecessary because the binary is setuid vortex8 already. Then the buffer address measured in gdb, ffff d two one two, the return address at buffer plus one sixty, and the sled sized to absorb the drift, one hundred eighty-seven bytes. The file is 34 lines, 898 bytes. I open vim and write the driver: a small C loader that reads the payload file and execs the level with it as the argument. The file is 6 lines, 244 bytes. I run the exploit with the buffer address piped in from gdb, and the driver loads the payload. The level's shellcode reads /etc/vortex_pass/vortex8 and prints the vortex8 password.
