Vortex, level one. The goal is a shell from /vortex/vortex1, a setuid binary that reads stdin one byte at a time, and only gives up a shell when its cursor reads 0xca in the top byte. The trick is two hundred sixty one backslashes to walk the cursor down to its own top byte, then four raw 0xca bytes through a pipe, because the keyboard hook refuses every byte at or above 0xc0. I log in as vortex1 and check the binary: setuid, thirty two bit, not stripped, and the stack is not executable. I disassemble main with objdump: the frame is 0x21c bytes, the buffer sits at ebp minus 0x21c, the cursor starts at buf plus 0x100, and a canary is loaded from gs. The loop dispatches on each byte: newline prints the whole buffer as hex, and backslash moves the cursor down one. Before every read it checks the cursor's top byte: if it reads 0xca, the shell branch fires. The shell branch calls geteuid three times, then setresuid, then execlp on /bin/sh. If the shell call ever returned, the fall-through would print the cursor. Any other byte is stored at the cursor, as long as the cursor is still inside the buffer, and the cursor advances one. The loop reads the next byte with getchar until end of file, then prints All done, checks the canary, and returns. I disassemble print as well: it prints the buffer one byte at a time as hex, then a newline. I open vim and write a small Python driver that pipes the raw bytes in: The driver imports subprocess, sys, and time, and the header comment records the trick: two hundred sixty one backslashes walk the cursor from buf plus 0x100 down to eight bytes above the saved frame pointer, and 0xca bytes give the branch its top byte. The comment finishes the story: 0xca cannot be typed, so it is passed raw on a pipe, the getchar hook only filters keyboard input, and stdin stays open so the shell is interactive. The driver takes the backslash count from the command line, default two hundred sixty one, builds the payload, spawns the program with a pipe, and writes it.
