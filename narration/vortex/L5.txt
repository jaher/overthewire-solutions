Vortex, level five. The goal is the vortex6 password, from /vortex/vortex5: a setuid vortex6 binary that hashes the getpass input with glibc's MD5 and compares sixteen bytes against a fixed digest, and gives up a shell when they match. The gate is the exact password, and the target hash is the MD5 of the password itself, so the solve is a preimage crack. I log in as vortex5. I make /tmp/l5rec, move in, and clear any old files. I open vim and write the cracker: it forks twenty workers over the alphanumeric space, each checking one first letter, for lengths one through five, hashing each candidate and comparing to the target digest. First the imports and the target: the digest read as bytes from hex, one five five f b nine five d, and the alphabet, letters plus digits. Then the worker: for this first letter it checks the short lengths first. Lengths one to four, every combination from the alphanumeric set. Then the five-character space: this first letter plus four more, each hashed with MD5 against the target. Then the pool: twenty processes, the first hit printed as FOUND, and the pool terminated. The pool maps the worker over every first letter, and stops at the first hit. The file is 29 lines, 924 bytes. I log out of the shell. Back on my own shell, I make a local directory and write the cracker there. It is the same twenty-worker search, written out again to run locally. The heredoc writes the whole file in one go: imports, target, worker, and pool. The local copy is 29 lines, the run finds the five-character password, the hash checks out, and I log back in to run it. Then I run the level directly, /vortex/vortex5, and type the cracked password, five characters, at the getpass prompt. The level says you got the right password, congrats, and spawns a shell. id confirms uid five thousand six, vortex6. And the password file reads back the vortex6 password. The level is solved. I log out.
