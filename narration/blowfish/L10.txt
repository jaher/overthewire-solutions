Blowfish, level ten. The README is empty - you're on your own. The binary is setuid level eleven. The disassembly tells the story. The program calls geteuid, passes it to setuid, then calls system with a string from rodata. Then it prints a prompt, reads up to one hundred twenty-seven bytes, sleeps two seconds, takes strlen of the buffer, and compares it against a negative constant that strlen can never return. So the password game itself is unwinnable - the comparison always fails and the program prints Incorrect password and Goodbye. The only code that matters happens before any of that: the system call. The rodata dump shows what system runs: the string clear, sitting right after a decoy password y zero y zero c zero n g r a seven s. system executes slash bin sh minus c clear - a shell that searches PATH for the first clear executable. And we control PATH. The exploit script is tiny. We write a shell script named clear that cats slash pass slash level eleven, make it executable, and run the binary with our directory first on PATH. The child shell that system spawns keeps the elevated effective U I D, so our clear runs as level eleven and reads the password file. Running it: our clear prints the level eleven password first - p h j three three r underscore t u X - then the game prints its irrelevant Incorrect password and Goodbye. Verified live: logging in as level eleven with p h j three three r underscore t u X succeeds. Level ten solved.
