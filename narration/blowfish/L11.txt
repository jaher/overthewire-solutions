Blowfish, level eleven. The README says good luck. The binary is setuid level twelve. The disassembly is short. strncpy copies at most sixteen bytes of argv two into a buffer at E B P minus eight - an eight-byte buffer, so a sixteen-byte copy already reaches past the saved base pointer into the return address. Then strlen of the buffer must equal exactly seven, which means argv two must be exactly seven characters - that is the gate. When it passes, the program runs strcpy of the buffer and argv ONE with no length limit at all. That is the real overflow. The environment: address randomization is off and the stack segment is readable, writable and executable. Same setup as earlier levels - a return address pointing into a NOP sled followed by the fifty-five byte setuid shellcode. The exploit script: twelve filler bytes reach the saved return address, then the guessed stack address, an eight-hundred-byte sled and the shellcode. argv two is seven characters to pass the gate. The probe forks the binary on a pseudo-terminal, sends I D, and checks for u i d one zero one two. One important detail: this kernel maps the stack just below zero c zero zero zero zero zero zero - not zero f f f f... like older boxes - and the per-user process limit is only twenty, so the probe reaps its children before and after every fork or it dies with resource temporarily unavailable. Running it: the probe lands at zero b f f f f b one zero, the shell answers u i d equals one zero one two level twelve, and it reads the level twelve password: e m underscore k c u F. Verified live: logging in as level twelve with e m underscore k c u F succeeds. Level eleven solved.
